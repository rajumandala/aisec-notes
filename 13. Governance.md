## What AI governance is

An architecture review checks **one** system. **Governance** is how an organisation makes sure **every** AI system is built, approved and run safely, including the ones nobody told the security team about.

It is the same idea as an AppSec programme: policies, an inventory of applications, risk ratings, required controls per rating, security gates, and evidence that the controls work.

## The parts

| Part | Meaning | Example |
|---|---|---|
| **Policy** | Rules everyone must follow | "Customer personal data may only be sent to approved model providers" |
| **Inventory** | A list of every AI system and what it is made of | The helpdesk assistant uses `gpt-6-luna`, 3 tools, 1 MCP server and the KB index |
| **Risk tiers** | Ratings that decide how much control a system needs | A read-only assistant is a lower tier than an agent that resets MFA |
| **Required controls** | What each tier must have before release | Higher tiers need a security review, an eval and a red team test |
| **Evidence** | Proof that the controls exist and work | Eval results, review sign-off, approval logs |
| **Monitoring and change management** | Keeping it safe after release | Re-run the eval when the model version changes |

## Policy: what to decide

| Topic | Example rule |
|---|---|
| Approved model providers | Only providers whose contract says they do not train on our data, with a known retention period |
| Data allowed in prompts | No passwords, keys or payment card data; personal data only with an approved provider |
| Approved MCP servers and tools | Only servers from the approved list, pinned to reviewed versions |
| Who may build agents that act | Agents that change data need a security review before release |
| Human approval | Actions on accounts, payments or external communication need a person to approve |
| Logging | What is logged, where, for how long, and whether traces may leave the company |

## Inventory: an AI bill of materials

For each AI system, record:

| Item | Example |
|---|---|
| Owner | IT helpdesk team |
| Models and versions | `gpt-6-luna`, `text-embedding-3-small` |
| Prompts | Stored in the repository, with version history |
| Tools and what they can change | `get_ticket` (read), `close_ticket` (write, approval needed) |
| MCP servers and frameworks, with versions | `tickets` server v1.2, OpenAI Agents SDK 0.23.1 |
| Data sources | Ticket system, knowledge base |
| Memory | None |
| Risk tier | 2 |

Without an inventory, you cannot answer "which of our systems are affected?" when a model is retired or an MCP server is found to be malicious.

## Risk tiers

Two questions decide the tier: **what can it do on its own**, and **how sensitive is the data and impact**.

| Tier | Description | Example | Required before release |
|---|---|---|---|
| 1 | Read-only, internal, no sensitive data | Summarises public KB articles | Approved provider, basic logging |
| 2 | Reads sensitive data, or acts with human approval | Analyst assistant that closes tickets after confirmation | Tier 1 + architecture review + eval with security cases |
| 3 | Acts without approval, or affects accounts, money, customers or external parties | Agent that resets MFA or emails customers | Tier 2 + red team test + monitoring with alerts + a way to switch it off |

## Evidence

Evidence makes governance real. For each system, keep:

- The architecture review and its findings, with how each finding was fixed or accepted
- Eval results for the current model and prompt version, including security cases
- Red team results for tier 3 systems
- Records of approvals for actions with consequences
- Accepted risks, with an owner and an expiry date, exactly like security exceptions today

## Change management

AI systems change in ways code reviews do not catch:

| Change | What must happen |
|---|---|
| New model or model version | Re-run the eval before switching |
| Prompt changed | Re-run the eval; the prompt is code |
| New tool, MCP server or data source | Update the inventory; review it if it raises the tier |
| Provider changes its terms | Check retention and training rules again |

## Incident response for AI

Plan these before an incident:

| Situation | Response |
|---|---|
| An agent is doing harmful things | A switch to turn the agent or a single tool off at once |
| A poisoned document or memory is found | Find and delete it, then find every session that used it |
| An MCP server is found to be malicious | Use the inventory to find every system that uses it, remove it, and rotate any tokens it held |
| Data was sent to the wrong place | Logs that show what the agent sent, to whom, and why |

## External frameworks and laws

| Name | What it is |
|---|---|
| **OWASP Top 10 for LLM Applications** and **for Agentic Applications** | Lists of the most important technical risks; useful as review checklists |
| **NIST AI Risk Management Framework** | A US framework for managing AI risk across an organisation |
| **ISO/IEC 42001** | An international standard for an AI management system, which can be certified, similar in style to ISO 27001 |
| **EU AI Act** | An EU law that sets obligations based on the risk level of the AI use |
| **India's Digital Personal Data Protection Act, 2023** | Applies when personal data is processed, including in prompts, logs and memories |

Which ones apply depends on your organisation and where it operates. Check the current requirements before relying on them, because this area changes quickly.

## Summary

| Lesson | Example |
|---|---|
| Governance makes every AI system safe, not just the one being reviewed | Policy, inventory, tiers, controls, evidence |
| An inventory lets you react when something changes | "Which systems use this MCP server?" |
| Risk tiers depend on what the system can do and what data it touches | MFA reset agent = tier 3 |
| A new model or prompt is a change that needs testing | Re-run the eval before switching |
| Evidence and accepted risks work like AppSec exceptions | Owner, reason, expiry date |
| Plan how to switch an agent off before you need to | A switch per agent and per tool |
